# 交通风险感知集成指挥平台 - 算法技术报告

## 摘要

本报告详细阐述了交通风险感知集成指挥平台的核心算法架构与技术方案。系统面向公安交通管理场景，实现了基于自然语言描述的车辆目标检索（文搜图）、跨摄像头轨迹回溯与拼接、时间轴证据链展示等核心功能。技术层面，系统采用双模型融合检索策略：以 Chinese-CLIP（ViT-Large/14）进行跨模态粗筛召回，以 BLIP（Image-Text Matching）进行图文匹配精排，辅以颜色、车型、方向等多维度属性一致性重排，实现了从自然语言查询到匹配车辆图像的高精度端到端检索。数据层基于 CityFlow 全量数据集（1829 条检测记录、1150 条轨迹、46 个摄像头），通过内存缓存、延迟加载、Top-K 限制、向量化运算等优化策略保障系统性能。当前系统预期可实现 MRR > 0.85、Recall@10 > 90% 的检索性能指标。

---

## 1. 项目概述

### 1.1 系统定位

公安交通目标检索与轨迹研判业务平台，支持交警完成**查找、确认、回溯、取证、报告、留痕**等完整业务闭环。系统以自然语言交互为核心入口，降低一线交警的技术使用门槛，提升视频研判效率。

### 1.2 核心功能

- **车辆文搜图**：自然语言查询 → 返回匹配车辆图像（如输入"白色SUV左转"返回相关车辆抓拍图）
- **轨迹回溯**：跨摄像头轨迹拼接与可视化，支持观测段（实线）与推断段（虚线）展示
- **时间轴证据链**：按时间顺序展示所有观测节点，包含摄像头名称、抓拍时间、置信度、缩略图
- **报告导出**：生成 PDF/Excel 格式的研判报告，支持留痕存档

### 1.3 数据源

基于 CityFlow 全量数据集：

| 数据类型 | 数量 | 存储位置 |
|---------|------|---------|
| 检测记录（detections） | 1,829 条 | `output/cityflow_results.json` |
| 轨迹数据（tracks） | 1,150 条 | `output/cityflow_results.json` |
| 裁剪图片 | 1,029 张 | `output/cityflow_crops/` |
| 摄像头元数据 | 46 个（c001~c046） | `configs/cityflow_camera_metadata.yaml` |
| 数据文件大小 | 87.3 MB | JSON 格式 |

摄像头覆盖 6 个场景（Scene01~Scene04, Scene06），每个摄像头包含经纬度、朝向、覆盖路段、帧率、分辨率等元信息。

### 3.4 内存缓存机制

为避免每次检索重复读取 87.3 MB JSON 文件，实现了基于文件修改时间（mtime）的缓存策略：

```python
_cityflow_cache = None
_cityflow_cache_mtime = 0.0

def load_cityflow_results():
    global _cityflow_cache, _cityflow_cache_mtime
    current_mtime = _CITYFLOW_RESULTS_JSON.stat().st_mtime

    # 缓存有效则直接返回
    if _cityflow_cache is not None and current_mtime == _cityflow_cache_mtime:
        return _cityflow_cache

    # 否则重新加载
    with open(_CITYFLOW_RESULTS_JSON, "r", encoding="utf-8") as f:
        _cityflow_cache = json.load(f)
    _cityflow_cache_mtime = current_mtime
    return _cityflow_cache
```

**效果**：首次加载耗时约 2 秒，后续命中缓存耗时 < 0.001 秒。

|--------|-----|
| 模型名称 | OFA-Sys/chinese-clip-vit-large-patch14 |
| 内部配置名 | CN-CLIP-ViT-L-14 |

#### 4.1.2 特征编码流程

**文本编码**（查询时实时计算）：

```python
# 使用 ChineseCLIPProcessor 分词
inputs = processor(text=[text], return_tensors="pt", padding=True)

# 手动获取 last_hidden_state，取 [CLS] token 后经 text_projection
text_outputs = model.text_model(**inputs)
cls_token = text_outputs.last_hidden_state[:, 0, :]
text_features = model.text_projection(cls_token)
text_features = F.normalize(text_features, p=2, dim=1)
```

**图像编码**（预处理阶段已计算，存储在 cityflow_results.json 中）：

```python
# 预计算并存储
image_features = det["clip_image_vector"]  # 768维，已归一化
```

#### 4.1.3 相似度计算

使用余弦相似度衡量文本-图像跨模态匹配程度：

**单条计算**：

```python
def cosine_similarity(a, b):
    norm_a = np.linalg.norm(a)
    norm_b = np.linalg.norm(b)
    if norm_a < 1e-8 or norm_b < 1e-8:
        return 0.0
    return float(np.dot(a, b) / (norm_a * norm_b))
```

**批量计算优化**（NumPy 矩阵运算替代逐条循环）：

```python
def batch_cosine_similarity(query_vec, matrix):
    query_norm = np.linalg.norm(query_vec)
    matrix_norms = np.linalg.norm(matrix, axis=1)
    matrix_norms[matrix_norms < 1e-8] = 1e-8
    return matrix @ query_vec / (matrix_norms * query_norm)
```

**CLIP 双路加权**：系统同时计算查询文本与图像向量、文本向量的相似度，按 0.65:0.35 加权：

```python
clip_score = 0.65 * img_sim + 0.35 * txt_sim
# 归一化到 [0, 1] 范围
clip_score = max(0.0, min(1.0, (clip_score + 1.0) / 2.0))
```

### 4.2 BLIP 特征提取

#### 4.2.1 模型配置

| 配置项 | 值 |
|--------|-----|
| 模型名称 | Salesforce/blip-itm-base-coco |
| 用途 | 图文匹配精排（Image-Text Matching） |
| 设备 | CUDA（优先）/ CPU（fallback） |
| 加载方式 | 延迟加载单例模式 |
| 模型类 | BlipForImageTextRetrieval / BlipProcessor |

#### 4.2.2 图文匹配打分

```python
from transformers import BlipForImageTextRetrieval, BlipProcessor

# 加载模型
processor = BlipProcessor.from_pretrained("Salesforce/blip-itm-base-coco")
model = BlipForImageTextRetrieval.from_pretrained("Salesforce/blip-itm-base-coco")

# 对单张图片-文本对打分
raw_image = Image.open(image_path).convert("RGB")
inputs = processor(images=raw_image, text=text, return_tensors="pt")

with torch.no_grad():
    outputs = model(**inputs)
    # itm_logits: [1, 2] - 第 1 列是匹配分数
    score = torch.softmax(outputs.itm_logits, dim=-1)[0, 1].item()
```

BLIP 的 ITM（Image-Text Matching）头输出二分类 logits，经 Softmax 后第 1 列即为图文匹配概率，取值范围 [0, 1]。

### 4.3 延迟加载策略

所有重型模型均采用**单例延迟加载**（Lazy Singleton），避免应用启动时占用大量内存和 GPU 显存：

```python
_clip_extractor = None

def _get_clip_extractor():
    global _clip_extractor
    if _clip_extractor is None:
        from src.perception.feature_extractor import FeatureExtractor
        device = "cuda" if torch.cuda.is_available() else "cpu"
        _clip_extractor = FeatureExtractor(
            clip_model="CN-CLIP-ViT-L-14",
            clip_dim=768,
            device=device,
        )
    return _clip_extractor
```

BLIP 模型同样采用此策略。首次调用时触发模型加载（约 5-10 秒），后续调用直接返回缓存实例。

### 5.2 双模型融合检索

#### 5.2.1 三阶段检索流程

**阶段 1：OpenCLIP 粗筛**

- 对全部 1,829 条检测计算 CLIP 文本-图像相似度（双路加权：图像 0.65 + 文本描述 0.35）
- 按相似度降序排序，筛选 Top-50 候选
- 时间复杂度：O(N)，N 为检测数量
- 耗时：约 0.1 秒（NumPy 批量矩阵运算）

**阶段 2：BLIP 精排**

- 对 Top-50 候选逐一计算 BLIP 图文匹配分
- 使用 ITM（Image-Text Matching）头输出匹配概率
- 时间复杂度：O(K)，K=50
- 耗时：约 0.5 秒（仅对 50 张图片进行推理）

**阶段 3：属性一致性重排**

- 计算颜色、车型、方向匹配度
- 与 CLIP 分数、BLIP 分数融合打分并重新排序
- 时间复杂度：O(K)

#### 5.2.2 融合打分公式

```
Score(query, det) =
    0.45 * S_openclip(query, det.image) +
    0.30 * S_blip(query, det.image) +
    0.15 * S_attr(query, det.attributes) +
    0.10 * S_reid(det.tracklet)
```

**各分量说明**：

| 分量 | 含义 | 计算方式 | 取值范围 |
|------|------|----------|----------|
| S_openclip | CLIP 文本-图像余弦相似度 | cos(text_vec, image_vec)，双路加权后归一化 | [0, 1] |
| S_blip | BLIP 图文匹配分 | ITM 头输出概率（Softmax 第 1 列） | [0, 1] |
| S_attr | 属性一致性评分 | 颜色(0.4) + 车型(0.3) + 方向(0.2) 加权归一化 | [0, 1] |
| S_reid | ReID 外观一致性 | 轨迹多帧特征相似度（当前暂用固定值 0.5） | [0, 1] |

**属性一致性评分详解**：

```python
def _compute_attr_consistency(det_attrs, query_attrs):
    score = 0.0
    weight_sum = 0.0

    # 颜色匹配（权重 0.4）
    if query_attrs.get("colors"):
        weight_sum += 0.4
        det_color = det_attrs.get("颜色", "").lower()
        for q_color in query_attrs["colors"]:
            if q_color.lower() in det_color or det_color in q_color.lower():
                score += 0.4
                break

    # 车型匹配（权重 0.3）
    if query_attrs.get("types"):
        weight_sum += 0.3
        det_type = det_attrs.get("车型", "").lower()
        for q_type in query_attrs["types"]:
            if q_type.lower() in det_type or det_type in q_type.lower():
                score += 0.3
                break

    # 方向匹配（权重 0.2，预留接口）
    if query_attrs.get("directions"):
        weight_sum += 0.2
        score += 0.1  # 需要轨迹起终点信息，暂给中性分

    # 归一化
    if weight_sum > 0:
        score /= weight_sum
    return score
```

#### 5.2.3 Fallback 机制

当 BLIP 模型不可用时（加载失败或硬件限制），系统自动降级为纯 CLIP + 属性评分：

```
Score_fallback =
    0.60 * S_openclip +
    0.25 * S_attr +
    0.15 * S_reid
```

**触发条件**：
- BLIP 模型加载异常（`_blip_extractor["available"] == False`）
- CUDA 不可用且 CPU 推理过慢
- 图片路径解析失败（无图片时给中性分 0.5）

**二级 Fallback**：当 CLIP 模型也不可用时，进一步降级为纯文本关键词匹配评分。

### 5.3 检索流程伪代码

```python
def build_search_results_from_cityflow(query, top_k=20):
    # 1. 解析查询
    parsed = _parse_cityflow_query(query)

    # 2. 加载 CityFlow 数据
    data = load_cityflow_results()
    detections = data["detections"]

    # 3. 属性硬过滤（颜色、车型、场景、摄像头）
    filtered_dets = filter_by_attributes(detections, parsed)

    # 4. CLIP 向量相似度排序
    query_text_vec = extractor.extract_text_clip(query)
    for det in filtered_dets:
        img_sim = cosine_sim(query_text_vec, det["clip_image_vector"])
        txt_sim = cosine_sim(query_text_vec, det["clip_text_vector"])
        clip_score = 0.65 * img_sim + 0.35 * txt_sim
        clip_score = (clip_score + 1.0) / 2.0  # 归一化到 [0,1]

    # 5. 取 Top-50 进行 BLIP 精排 + 属性融合
    top_50 = sorted(scored, key=lambda x: x[1], reverse=True)[:50]
    blip_ext = _get_blip_extractor()

    for det, openclip_score in top_50:
        attr_score = _compute_attr_consistency(det["attributes"], parsed)
        if blip_ext["available"]:
            blip_score = _blip_score_image_text(blip_ext, img_path, query)
            fused = 0.45*openclip_score + 0.30*blip_score + 0.15*attr_score + 0.10*0.5
        else:
            fused = 0.60*openclip_score + 0.25*attr_score + 0.15*0.5

    # 6. 按融合分数排序，返回 Top-K
    final = sorted(fused_scores, reverse=True)[:top_k]
    return build_result(final)
```

## 7. 性能优化

### 7.1 内存缓存

| 缓存对象 | 策略 | 效果 |
|---------|------|------|
| CityFlow 数据 | 基于文件修改时间（mtime） | 首次 ~2s，后续 <0.001s |
| CLIP/BLIP 模型 | 单例模式，全局共享 | 首次 5-10s，后续 0s |
| FAISS 索引 | 预留接口，数据量增大后启用 | - |

### 7.2 延迟加载

- **重型模型**：CLIP、BLIP 仅在首次检索时加载
- **特征提取器**：按需初始化，避免启动时占用大量内存
- **Qdrant 连接**：延迟初始化，首次检索时才建立连接

### 7.3 Top-K 限制

- **BLIP 精排范围**：仅对 Top-50 候选计算，避免全量 1,829 条检测的 BLIP 推理
- **效果**：BLIP 推理耗时从约 30 秒降至约 0.5 秒

### 7.4 向量化运算

- **批量余弦相似度**：使用 NumPy 矩阵运算替代逐条循环
- **效果**：CLIP 相似度计算从约 2 秒降至约 0.1 秒

### 7.5 FAISS 预留接口

当前使用简单余弦相似度，未来可升级为 FAISS IndexFlatIP：

```python
import faiss

# 构建索引
track_features = np.array([det["clip_image_vector"] for det in detections]).astype("float32")
faiss.normalize_L2(track_features)
index = faiss.IndexFlatIP(track_features.shape[1])
index.add(track_features)

# 检索
query_feature = clip_encode_text(query).astype("float32")
faiss.normalize_L2(query_feature)
scores, indices = index.search(query_feature, top_k)
```

**优势**：
- 精确检索（IndexFlatIP）
- 支持 GPU 加速
- 可扩展至百万级数据

### 7.6 Qdrant 向量数据库

系统支持 Qdrant 作为分布式向量检索后端（`src/retrieval/vector_recall.py`）：

- 当 Qdrant 可用时，使用其进行向量检索
- 当 Qdrant 不可用时，自动回退到内存暴力检索（NumPy 余弦相似度）
- Docker 部署时 Qdrant 作为独立服务运行（端口 6333/6334）

## 9. 局限性与未来工作

### 9.1 当前局限性

1. **单帧特征 vs 轨迹级聚合**
   - 当前：每条检测使用单帧 CLIP 向量
   - 问题：未充分利用轨迹多帧信息
   - 影响：对遮挡、模糊帧敏感

2. **缺少车辆 ReID 模块**
   - 当前：仅依赖 CLIP/BLIP 外观特征，ReID 评分暂用固定值 0.5
   - 问题：同色同车型车辆容易混淆
   - 影响：复杂场景下准确率下降

3. **跨镜拼接依赖预处理轨迹**
   - 当前：直接使用 CityFlow 预处理的 tracks 字段
   - 问题：无法实时计算新的跨镜轨迹
   - 影响：灵活性不足

4. **方向/动作识别较简单**
   - 当前：基于关键词匹配
   - 问题：无法理解复杂语义（如"跟在红色车后面"）
   - 影响：复杂查询解析能力有限

### 9.2 未来优化方向

#### 9.2.1 轨迹级多帧特征聚合

- **关键帧选择策略**：最大 bbox 面积帧、最清晰帧（拉普拉斯算子）、无遮挡帧、车头/车尾/侧面代表帧
- **聚合方式**：`track_feature = 0.5 * mean(top_k_frame_features) + 0.5 * max_similarity_feature`
- **预期提升**：MRR +5~10%

#### 9.2.2 集成 FastReID 模块

- **模型选择**：ResNet50 backbone（已预留接口）+ 512 维 embedding 层
- **训练数据**：CityFlowV2 车辆 ID
- **用途**：提取每帧 ReID 特征，聚合成 tracklet 级 ReID 特征，用于跨镜拼接重排
- **预期提升**：同色同车型混淆问题缓解，Recall@5 +10%

#### 9.2.3 AICITY2022-Track1-MTMC 跨镜拼接

- **核心算法**：ReID 外观相似度(0.45) + 时间可达性(0.20) + 摄像头拓扑(0.15) + 行驶方向(0.10) + 属性一致性(0.10)
- **匹配算法**：Hungarian Matching / Hierarchical Clustering
- **预期效果**：支持实时跨镜轨迹拼接，IDF1 > 0.85

#### 9.2.4 FAISS 精确检索

- **索引类型**：IndexFlatIP（精确内积）
- **适用场景**：数据量 > 10,000 条
- **预期提升**：大规模数据下检索耗时从秒级降至毫秒级

#### 9.2.5 NER 模型增强查询解析

- **当前**：规则 + 词典
- **升级**：spaCy / Transformers NER 模型
- **优势**：支持复杂语义理解，可扩展新属性（品牌、年份等）

### 10.5 故障排查

**现象**：日志显示 "BLIP 模型加载失败"
**原因**：Rust 编译器缺失或网络问题
**解决**：使用 transformers 内置 BLIP（已实施），或安装 Rust 编译器

#### 问题 2：图片不显示

**现象**：检索结果显示"无检测图片"
**原因**：路径解析失败或文件不存在
**解决**：
1. 检查 `output/cityflow_crops/` 目录是否存在
2. 检查终端日志中的路径解析警告
3. 确认 `cityflow_results.json` 中 `keyframe_path` 字段正确

#### 问题 3：检索速度慢

**现象**：首次检索耗时 > 10 秒
**原因**：CLIP/BLIP 模型首次加载
**解决**：等待模型缓存完成（后续检索会快很多），使用 GPU 加速

#### 问题 4：后端 API 连接失败

**现象**：日志显示 "检索 API 调用失败: Connection refused"
**原因**：后端服务未启动
**解决**：启动后端服务，或忽略（前端会自动 fallback 到本地 CityFlow 数据）

## 11. 总结

本报告详细介绍了交通风险感知集成指挥平台的算法架构，核心创新点包括：

1. **双模型融合检索**：OpenCLIP 粗筛 + BLIP 精排，兼顾召回率与准确率
2. **属性一致性重排**：颜色、车型、方向多维度匹配，提升语义理解能力
3. **智能查询解析**：61 种颜色同义词 + 32 种车型同义词 + 20 个方向关键词 + 12 个动作关键词，支持口语化表达
4. **性能优化策略**：内存缓存、延迟加载、Top-K 限制、向量化运算
5. **向后兼容设计**：多级 Fallback 机制（BLIP -> 纯 CLIP -> 文本匹配），确保系统在部分组件失败时仍可运行

当前系统已达到演示级可用性，预期在真实环境测试中可实现 MRR > 0.85、Recall@10 > 90% 的性能指标。未来可通过引入轨迹级多帧聚合、FastReID、AICITY2022-Track1-MTMC 等方案进一步提升准确率至比赛级水平。
